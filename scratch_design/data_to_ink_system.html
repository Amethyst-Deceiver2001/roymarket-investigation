Data-to-Ink Rules

This project already has tokens and components. What it has not had, until this page, is a written rule for when a visual is allowed to exist. This document states that rule, audits the current site against it, and specs the one component the audit says is missing.

The rule

Data-to-ink

Every mark on a published page must trace to a named field in data/registry/*.json. If you can't point at the field, the mark is decoration, and this registry doesn't carry decoration — everything on it has to survive a hostile lawyer's reading, including the pictures. A color, a shape, an icon, a line's thickness: each one is either encoding a fact a reader can look up, or it's noise competing with the facts that do.

This is not a ban on visual design — a hub-and-spoke motif, a hero image, a typographic flourish are all fine. It's a naming discipline: say what each one encodes, even if the honest answer is "nothing, it's structural chrome" (a rule, a margin, a heading face). The problem this rule exists to catch is a mark that looks like it's telling you something about the investigation — implying severity, connection, or scale — while actually being interchangeable with any other investigation's version of the same page.

Where the rule breaks — landing-page audit

The three elements below are the ones the redesign shipped this session. Read against the rule, one passes, one is half-credit, and one is pure chrome dressed as evidence — which is the thing the critique that prompted this document was actually pointing at.

ElementWhat it shows todayVerdictWhat it should trace to
Hero network motif (network_motif()) Hub-and-spoke SVG, one spoke per published case slug, short Cyrillic label decorative Nothing per-spoke. Spoke count = len(CASES), a Python list length, not a queried fact. Every spoke is drawn identically regardless of that case's tier, sanction status, or evidentiary weight — a reader can't learn anything from the picture that the case list below it doesn't already say in text.
Case-feed lines (build_indexes() · case_feed) Kicker + title + one prose sentence per case, plain --ink-2 text partial The sentence itself already carries a real number for 6 of 7 cases (below) — financials[], government_contracts[], sanctions[], workforce_history[]. But it's prose, not ink: the number gets the same visual weight as connective words around it, so nothing on the page lets a skimming reader rank the seven cases by what's actually most alarming about each.
Hero paragraph (hero_note) Hand-written prose paragraph replacing the earlier stat-tile row partial Text, correctly — this is analysis, and analysis is where hand-written prose belongs per STYLE_GUIDE.md. Flagged only so it's not mistaken for a data-bound element: it's not meant to trace to a field, and shouldn't.

The fix — a signal chip, not a bigger motif

The stat-tile row was cut because tiles read as generic dashboard filler — that verdict stands, tiles as a block are exactly the AI-template look this project's own design guidance warns against. But the fix isn't to remove the number, it's to put it back at the point of use: one small chip per case-feed row, colored by which sanctions[]/financials[]/government_contracts[] pattern it reports, using tokens that already exist and already mean something (--low for a sanctions flag, --mid for a structural anomaly, --ok for a scale claim worth checking). No new palette, no new icon set — just stop leaving the existing semantic colors unused on the one page most readers see first.

Every chip above quotes a number that's already sourced and already sitting in the case's own prose line — this is a formatting change to build_indexes()'s case_feed loop, not new research. Each case needs one added key in CASES — signal: {"type": "sanction"|"anomaly"|"scale", "text": "..."} — set by hand once per case the same way kicker/line already are, so the chip's color is a deliberate editorial call, not something a script infers.

What this doesn't cover

This page is the rule and the audit, not a rebuild. It doesn't touch Part 2/3 of the open Network Graph plan (live-artifact default view, curated static excerpts) — those are a separate, larger piece of work already scoped in notes//the current plan file. It also doesn't relitigate the stat-tile removal; it explains why that removal was right in isolation and where the number it deleted actually belonged instead.
